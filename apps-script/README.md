# Connecting the console to the school workbook

Fifteen minutes, once, in the school's Google account. After this the console
reads and writes the workbook directly, and every device that connects with the
same URL and token sees the same marks.

You do **not** need a Google Cloud project, a client ID, or a consent screen.
The script runs as the account that deploys it, so it can write the sheet and
save reports to Drive using that account's own permissions.

---

## 1. Open the script editor

Open the monitoring workbook —

[GBMHS Layyah — Monitoring Workbook](https://docs.google.com/spreadsheets/d/1jqDC2AqgoCmKjdgOg4MGJomjmR1upXKahRgGPWQXrkw/edit)

— then **Extensions → Apps Script**.

## 2. Paste the bridge

Delete whatever is in `Code.gs` and paste the whole of [`Code.gs`](Code.gs).

Optional but tidier: open the file list, choose **Project Settings → Show
"appsscript.json" manifest**, and replace it with the [`appsscript.json`](appsscript.json)
in this folder. It sets the time zone to Asia/Karachi and the web-app access the
console needs.

## 3. Run the setup function

In the editor choose the function **`setup`** from the dropdown and press **Run**.

- Google asks for permission the first time. Choose **Review permissions → your
  account → Advanced → Go to (unsafe) → Allow**. "Unsafe" is what Google says
  about any script you wrote yourself; nothing is shared with a third party.
- When it finishes, open **View → Logs** (or the Execution log panel). You will
  see a line like:

  ```
  SYNC_TOKEN = 7f3c1a9e2b804d5c9a61f0e4
  ```

  That token is the only thing protecting the school's record. Copy it.

`setup` creates two tabs, **Sync log** and **Settings**, and records the
workbook's id. It is safe to run again — it will not overwrite an existing token.

## 4. Deploy as a web app

**Deploy → New deployment →** gear icon **→ Web app**, then:

| Setting | Value |
|---|---|
| Description | `Monitoring console` |
| Execute as | **Me** (your account) |
| Who has access | **Anyone** |

Press **Deploy** and copy the URL ending in `/exec`.

> **Why "Anyone".** The console runs in the principal's browser and has no
> Google sign-in of its own, so the endpoint has to be reachable without one.
> The `SYNC_TOKEN` is what keeps it private: without the token every request is
> refused, and the sheet is not otherwise exposed. If you would rather not rely
> on that, see *Keeping it closed* below.

## 5. Connect the console

Open the console → **Data & Sync** → **Google Sheets storage** → paste the
`/exec` URL and the token → **Connect and test**.

You should see "Connected" and the number of changes already in the sheet. From
then on:

- every mark is saved on the device immediately and reaches the sheet within a
  few seconds;
- the sync chip in the masthead shows *queued*, *synced* or *error*;
- a full read happens every minute and whenever the browser comes back online.

## 6. Point Drive saves at the archive folder

Reports generated by the console are saved through the script. To keep them in
the existing folder rather than My Drive:

1. In the script editor's **Project Settings → Script Properties**, add
   `DRIVE_FOLDER_ID` with the value
   `1scGOXrHtu7aC255lcaX-YfeIYySxPQBT`
   (that is *School Monitoring — GBMHS Layyah*).
2. Or run `setFolder('1scGOXrHtu7aC255lcaX-YfeIYySxPQBT')` once from the editor.

Then **Reports → Save report to Drive** drops the current report into that
folder as a file you can sign and share.

## What the script does, and does not do

| It does | It does not |
|---|---|
| Appends every change to **Sync log**, never editing or deleting a row | Compute any score — the console sends the finished tables |
| Hands back changes newer than the caller's cursor | Hold a copy of the rubric or the marks elsewhere |
| Rewrites the readable tabs when the console sends them | Read or modify any other spreadsheet |
| Saves report files into the Drive folder you nominate | Upload to any folder you have not named |

Every formula lives in `js/scoring.js`. The script stores and displays, so the
numbers in the sheet and the numbers on screen cannot drift apart.

## How conflicts are handled

Two people can mark at the same time. Each change carries a timestamp, and the
newest timestamp for a given cell wins. The clock is corrected against the
server on every read, so a laptop with a wrong clock does not overwrite newer
work. Nothing else is touched — a mark in one cell never overwrites another.

If the log is ever emptied by hand, the console detects that its cursor is
beyond the end, replays from the first row, and records that it did so.

## Keeping it closed

If "Anyone" is not acceptable, two safer arrangements work with the same script:

- **Restrict the deployment** to "Anyone within <organisation>", and have the
  principal sign in to Google in the browser first. The console will then rely
  on the browser's existing Google session. This works in Chrome when the
  session is active, and fails quietly otherwise.
- **Keep the deployment private** and reach the sheet only through the manual
  export on the Data & Sync screen. The console still works fully offline.

## Changing the token

1. **Project Settings → Script Properties → SYNC_TOKEN →** edit.
2. Reconnect every device with the new value. Until you do, those devices show
   *Sheet: error* and queue their changes locally — nothing is lost.

## If something goes wrong

| Symptom | Cause | Fix |
|---|---|---|
| `Wrong token` | The console and the script disagree | Re-copy the token; check for a trailing space |
| `No SYNC_TOKEN set` | `setup` was not run | Run `setup` from the editor |
| `The sheet did not respond` | Deployment is not "Anyone", or the URL is the `/dev` one | Redeploy; use the `/exec` URL |
| Sync chip stuck on *queued* | No internet, or the endpoint is failing | Marks are safe locally; press **Sync now** in Data & Sync |
| Sheet tabs look stale | Only the change log syncs automatically | Press **Write workbook tabs** in Data & Sync |
| `The sheet is busy` | Two devices pushing at once | Retries automatically; the lock is held for 30 seconds at most |

## Checking it from a terminal

With the URL and token to hand:

```bash
curl -sL "https://script.google.com/macros/s/…/exec?action=ping&token=YOUR_TOKEN"
```

returns the script version, the number of rows in the log, and the recent ids.
If that works but the console does not, the token in the console is wrong.
